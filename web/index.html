Today, agent authorization is a hardcoded if statement. Or nothing at all.

Who decided this?

An agent spends $500. Who authorized it, within what limits, and can you prove it later? Right now the answer is buried in application code — or missing entirely.

No scoped autonomy

An agent either has a credential or it doesn't. There is no standard way to say "up to $200, three times, for one hour, then it expires."

No provable record

When something goes wrong, logs can be edited. There is no tamper-evident account of what an agent was permitted to do — and did.

Everyone is building agents. Almost no one is building the software agents depend on to act safely. conduit is that software.

The kernel

Three primitives. One question.

May this agent take this action, right now? conduit answers it by consulting two layers — and records the verdict in a hash-chained log.

01

Permissions

Coarse, always-on policy.

rules: [
  { action: 'web.*',     behavior: 'allow' },
  { action: 'system.*',  behavior: 'deny'  },
  { action: 'payment.*', behavior: 'ask'   },
]

deny always wins. No rule? Falls through to capabilities.

02

Capabilities

Scoped, budgeted, expiring autonomy.

conduit.grant({
  agentId: 'agent.shopper',
  action:  'payment.charge',
  constraints: {
    budget: { currency: 'USD', limit: 200 },
    rateLimit: { maxInvocations: 1, windowMs: 60000 },
  },
  expiresAt: Date.now() + 3600_000,
})

How an agent is trusted to act without a human — safely.

03

Audit

A tamper-evident record of everything.

// every decision is SHA-256 hash-chained
conduit.verifyAudit()
→ { valid: true, length: 12 }

// alter any past event and
// every later hash breaks

Tampering is detectable. The record is evidence.

The universal integration — wrap one call around tool execution:

const outcome = await conduit.run(
  { agentId, action: 'payment.charge', input, cost: { currency: 'USD', amount: 80 } },
  async () => actuallyChargeTheCard(input),
)
if (outcome.status === 'allowed')        { /* it ran */ }
else if (outcome.status === 'needs_approval') { /* route to a human */ }

Machine-readable by default

An agent discovers conduit on its own.

Software for agents starts before sign-up: an agent should land on a service and figure out what it can do — with no human reading docs. conduit serves two unauthenticated discovery routes: a .well-known agent manifest and a full OpenAPI 3.1 contract. The manifest carries an ordered, machine-readable onboarding runbook the agent simply follows. 

$ curl conduit.example.com/.well-known/agent-manifest.json

{
  "kind": "agent-authorization-service",
  "onboarding": { "steps": [
    { "step": 1, "name": "register",             "path": "/api/agents" },
    { "step": 2, "name": "request a capability", "path": "/api/capability-requests" },
    { "step": 3, "name": "authorize an action",  "path": "/api/authorize" },
  ] },
  "documentation": { "openapi": "/openapi.json" }
}

Both routes stay public even in commercial mode — an agent reads them before it holds any credential, then onboards itself.

No human in the loop

Agents onboard themselves.

"Software for agents" means an agent can discover a tool, sign up for it, and start using it programmatically. conduit makes that the normal path: an agent registers, gets a token, and requests its own capabilities. Requests inside policy are granted instantly; anything bigger is parked for a human.

  • Self-service registration with hashed, single-issue tokens
  • Policy-bounded auto-approval — budget and rate ceilings
  • Over-policy requests escalate cleanly to human approval
// 1. the agent signs itself up
const { token } = conduit.registerAgent({
  agentId: 'agent.shopper',
})

// 2. it requests its own capability
const result = conduit.requestCapability(
  'agent.shopper', token,
  { action: 'payment.charge',
    constraints: { budget: { currency: 'USD', limit: 40 } } },
)

→ { status: 'granted',  capability }
→ { status: 'pending',  approvalId }
→ { status: 'rejected', reason }
